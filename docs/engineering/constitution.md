# PipuPath Engineering Constitution

**Status:** Locked  
**Authority:** Primary engineering authority  
**Effective:** 2026-07-24  
**Adventure amendment:** 2026-08-20

## Mission

PipuPath must move a person through one coherent loop:

1. Join.
2. Discover early potential signals.
3. Select a Journey.
4. Develop through HQLS Quests.
5. Create evidence.
6. Evolve the Human Potential Profile.
7. Build a Project.
8. Find relevant Builders.
9. Collaborate.
10. Deploy capability.
11. Record outcomes.
12. Create credible impact.
13. Receive a larger developmental opportunity.

PipuPath is complete only when development inside the platform becomes useful outside the platform.

## Governing principles

1. **One operating system.** Capabilities must advance the same developmental loop, not become disconnected feature islands.
2. **Truthful state.** Never present fabricated data, fake persistence, simulated intelligence, or a completion state that the system cannot prove.
3. **Persistent by design.** Important user state must have an explicit owner, lifecycle, durable representation, and recovery strategy.
4. **Explainable decisions.** Recommendations and profile changes must retain their evidence, rules, model/version provenance, and user-visible rationale.
5. **Secure by default.** Authorization is enforced at data and action boundaries. UI visibility is not authorization.
6. **Privacy by necessity.** Collect the minimum developmental data required, classify sensitive data, define retention, and protect young users.
7. **Accessible and inclusive.** Core journeys must work with keyboard, assistive technology, reduced motion, narrow screens, and constrained connectivity.
8. **Testable slices.** A capability is incomplete without deterministic tests at the lowest useful level and an end-to-end proof of its critical path.
9. **Observable operation.** Failures and important transitions must produce structured, privacy-safe telemetry.
10. **Stage discipline.** Implement only the authorized stage. Record completion evidence and stop at its boundary.
11. **Replaceable infrastructure.** Domain rules must not depend directly on vendors, frameworks, transports, or model providers.
12. **Human agency.** AI may clarify, synthesize, or recommend; it must not silently define a person, fabricate evidence, conceal uncertainty, or trap a Builder in a developmental direction they can no longer change.
13. **Adventure architecture.** PipuPath is a Human Potential Adventure System. `docs/product/adventure-experience-constitution.md` is a mandatory product-experience authority. Builder-facing work that technically functions but reduces the experience to dashboard navigation, generic cards, long report pages, form funnels, or feature catalogues is architecturally incomplete.
14. **Life is the game.** Meaningful progress, XP, capability growth, unlocks and achievements must result from real developmental action and credible evidence, not screen activity for its own sake.
15. **History is immutable developmental evidence.** Changing a Path, Mission or developmental direction must not rewrite or erase truthful prior Missions, Quests, Evidence, Reflection, XP, Projects or Capability provenance. Direction changes are explicit transitions with retained lineage.
16. **Agency before rigidity.** Where human development can reasonably change direction, the product must support bounded choice and safe pivoting rather than forcing completion of an obsolete path merely because earlier software state exists.
17. **Experience drift blocks expansion.** A major new product layer must not be started while primary released Builder flows materially violate the locked Adventure Experience Constitution, unless the user explicitly overrides that gate.

## Adventure architecture release gate

Every primary Builder-facing slice must satisfy all applicable conditions before it is considered complete:

- the Builder can tell where they are in the larger adventure;
- one next meaningful real-world move is visually dominant;
- the interface shows what changes when that move is completed;
- Journey progression is spatial, staged, unlock-based or otherwise consequential rather than merely a list of records;
- Quest interaction follows `Understand → Act → Prove → Reflect → Reveal`;
- long explanations are progressively disclosed rather than dominating the main path;
- rewards are grounded in truthful action/evidence;
- failure produces useful developmental information and a next move;
- pivots preserve prior history and provenance;
- mobile, accessibility, privacy, safeguarding and recovery remain intact.

A passing unit test suite does not waive this gate.

## Definition of done

A vertical slice is done only when its behavior, persistence, authorization, validation, error states, accessibility, logging, tests, **adventure experience**, and implementation record are complete.

## Final rule

Build PipuPath as one coherent human-development adventure operating system, not as a collection of attractive screens or disconnected features. Every capability must be persistent, explainable, secure, testable, evidence-grounded and connected to the Builder's movement from discovery to development, deployment, contribution and impact.

**If implementation convenience conflicts with truthful human-development adventure architecture, the adventure architecture wins unless the user explicitly changes this constitutional authority.**
