# Domain map

| Domain           |  Stages | Responsibility                                                         | Launch boundary                          |
| ---------------- | ------: | ---------------------------------------------------------------------- | ---------------------------------------- |
| Platform         | 0–1, 10 | Runtime, design system, validation, observability, routing and release | No simulated product state               |
| Identity         |   2, 10 | Authentication, profile, consent, safeguarding and progression         | No public private-profile projection     |
| Discovery        |       3 | Fifteen-question private evidence lifecycle                            | Evidence before interpretation           |
| Human Potential  |       4 | Private validated profile synthesis and feedback                       | AI supports; it does not define identity |
| Mission          |       5 | One practical direction                                                | No invented achievement                  |
| Journey          |       6 | Ordered milestone plan                                                 | No simulated execution                   |
| Quest            |       7 | Action, private evidence, reflection and XP                            | Completion requires proof                |
| Project          |       8 | Useful real-world output and append-only updates                       | Private by default                       |
| Portfolio        |       9 | Selective adult public proof                                           | Eleven allow-listed fields only          |
| Launch readiness |      10 | Integration, visual coherence, accessibility and release candidate     | No new major product capability          |

The authenticated progression resolver composes domain status without owning any
domain data. Build routes contextualize existing Quest and Project capabilities;
they do not create a new Build domain.
