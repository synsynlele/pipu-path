# The Unbuilt City — first playable episode

User authority: 27 October 2026. Build the proposed game inside PipuPath and reuse
the existing platform design. This explicitly expands the previous life-first
experience with an in-screen practice adventure; the existing developmental
engine remains authoritative for real-world evidence, capability and XP.

## Delivered slice

Build links to `/build/play`, inside its existing authenticated layout and five-tab
AppShell. Reuses Button, card styles, indigo/white surfaces, brand, typography and
mobile navigation. No parallel app, account system, database or design template.

The first episode is a fictional neighbourhood gathering. Three resident stories
lead to a role choice, a shared-first planning attempt, explicit teaching, a changed
independent rain scenario, reflection and an optional five-step real-world experiment.
Solo play is explicit. A first success is permitted; failure is never required.
Roles change orientation clues; they are not separate career simulations yet.

The deterministic simulation separates supplies, hours and helper constraints,
accessibility, invitations, enjoyable activities and weather. Fictional visitor and
enjoyment numbers are visible game rules, not evidence of real-world outcomes.
The square updates with the selected builds. Editing invalidates prior test results.

## Truth and privacy

Practice earns no XP and makes no capability or career inference. No AI or camera
is used. Reflection and decisions stay in React page state and reset on refresh.
An explicit download creates a device-local JSON experiment record, labelled as
practice, not verified evidence. It does not upload content, create a Quest or
claim a real-world action occurred. Existing Quest evidence remains authoritative;
users are told to use it only when the experiment actually fits that Quest.

## Repeatable content production

Episode editor (future assigned product role) owns resident stories, build options,
constraints, changed scenario and no-cost real-world bridge. QA owns solvability,
clear language and mobile checks. A learning reviewer owns HQLS fidelity and transfer.
The founder does not approve each episode. New episodes should use versioned domain
contracts and tested constraints, rather than fork screens. This first episode is
fixed content; an episode editor, multiplayer, catalogue and automatic portfolio
integration are not implemented.

## Validation and rollout

Domain tests enumerate all 64 plans under both conditions, including duplicates,
resource bounds, feasible solutions and changed-condition failures. Component tests
exercise both attempts, role choice, stale feedback removal, reflection and replay.
Run the repository's full validation before release. Browser and production status
must be recorded separately from automated checks. Entertainment/return rate has
not been measured; do not claim this is a validated retention engine.

Pilot owner: a facilitator other than the founder. Observe a small consented group
without coaching: can they start, explain choices, retry voluntarily and choose a
safe real-world experiment? Record confusion, voluntary second play, return to an
attempt and actual experiment feedback. Do not infer psychometric validity.

## 27 October — visual play and connected journey revision

User requested graphic-first play and integration with the existing Journey.
The chapter now uses an optimised 284 KB WebP dusk environment, six illustrated
interactive sites, coherent SVG resource/action icons, short character speech,
resource meters, visible targets, rain and crowd feedback. Longer rules and
explanations are behind labelled details. Keyboard labels retain every site's
cost and effect; reduced-motion styles disable rain/build/crowd animation.

One shared Play → Act → Prove → Grow card is composed into Home (when a Journey
exists), Build, active Journey and Quest focus. It uses the actual current Quest.
The protected game route accepts an owned, unlocked Quest ID; malformed, foreign
and locked IDs fail closed. The final game step displays that Quest's real goal
and returns to its existing action/proof/reflection workflow. Existing proof is
prioritised over replay. No simulated result completes a Quest or earns XP.
An exact `/build/play` auth-return entry preserves the requested game destination
without opening arbitrary Build URLs.

This is the first connected chapter, not an automatically generated game for
every Quest. Common planning/listening practice is explicitly labelled. No backend
schema, real learner data, XP, evidence or capability writes were introduced.
Practice state remains tab-local and resets on refresh; private real-world
progress continues through the durable Quest engine. Cross-device game saves
and a catalogue of subject/skill-specific chapters remain future work.
