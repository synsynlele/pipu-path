# PipuPath Growth Pack Direction v1.0

**Status:** LOCKED PRODUCT DIRECTION ADDENDUM  
**Authority:** Human Potential Adventure learning-support pattern  
**Effective:** 2026-08-19  
**Product:** PipuPath  
**Company:** KAEC-NG

## Decision

PipuPath may recommend books, courses, skills and deliberate practice to a Builder, but learning support must never become a disconnected content catalogue.

The authoritative pattern is:

> **Growth Pack = what may help this Builder's current adventure now.**  
> **Growth Library = where previous Growth Pack suggestions can be revisited later.**

A recommendation exists to improve the next real-world developmental action. Reading, watching or enrolling is not progress by itself.

## Product placement

### Primary: contextual Growth Pack

Growth Pack recommendations are generated by the existing Personal Builder Guide using the Builder's current private PipuPath context, including where available:

- Human Potential / Living Builder evidence;
- selected Possible Path;
- active Mission / Campaign;
- active Journey chapter;
- current Quest;
- current Project / Major Build;
- known capability evidence gaps.

A Growth Pack may contain up to three items:

1. **Book** — a specific stable title/author only when the recommendation system is confident the resource is real; otherwise recommend the kind of book to seek.
2. **Course** — a useful course topic and, when appropriate, a reputable provider to investigate. Current availability, fees, certificate status, age rules and enrolment must never be invented.
3. **Skill** — a concrete capability to practise because it directly supports the current developmental challenge.
4. **Practice** — a bounded exercise that converts learning into action.

The Builder Guide question for this pattern is:

> **What should I learn, read or practise next?**

### Secondary: Growth Library

`/growth` is the private Growth Library.

It stores no separate recommendation database in Stage 22. It reads the Builder's already-versioned Builder Guide history and surfaces saved Growth Pack items with their original development context.

The Library is a reference tool, not a feed. It must not use infinite scroll, popularity ranking, sponsored placement or manipulative content discovery.

## Learning-to-action rule

Every Growth Pack item must explain:

- **why now** — which current challenge/evidence gap makes it relevant;
- **how to use it** — how the Builder should convert learning into a real action;
- **verification note** — what external facts still need to be checked.

PipuPath should encourage the pattern:

`Learn one useful idea → practise it → create evidence → reflect → decide what to learn next`

It should discourage:

`collect books/courses/certificates → feel productive → create no evidence`

## Resource integrity

PipuPath must not:

- invent URLs;
- invent current course availability;
- invent prices, discounts, enrolment windows or certificates;
- imply paid content is required for progress;
- claim a book/course guarantees success, income or capability;
- reproduce copyrighted book text beyond legally safe quotation limits;
- treat course completion as verified capability without PipuPath evidence;
- recommend gambling, speculative trading, borrowing or get-rich material;
- create sponsored ranking without an explicit future commercial-policy authority.

For course recommendations, the Builder must be told to verify current information using the provider's official source before enrolling or paying.

## Youth safety

For minors, recommendations must be age-appropriate.

PipuPath must not use a Growth Pack to route a minor toward:

- adult-only platforms;
- unsafe unsupervised work;
- contacting unknown adults;
- high-risk financial activity;
- content or communities that bypass PipuPath safeguarding boundaries.

Where external provider age rules or payment are relevant, the recommendation must explicitly tell the Builder to verify the activity with a responsible adult or institution.

## Evidence and progression

Growth Pack interaction itself earns no XP.

Reading a book, opening a course or viewing a suggestion does not strengthen a capability claim.

Progress occurs when the Builder applies learning in a genuine Quest, Project, collaboration or other authorised developmental action and produces evidence that the existing PipuPath engine can evaluate.

## Stage 22 implementation boundary

Stage 22 may:

- extend the Builder Guide output contract with backward-compatible Growth Pack data;
- add the `growth_support` Guide intent;
- add the private `/growth` Growth Library;
- reuse existing Builder Guide JSON history rather than add a new Supabase table;
- expose Growth Library from Profile/Builder tools and contextual adventure surfaces;
- add tests for backward compatibility, safety and fallback behaviour.

Stage 22 must not:

- build a full LMS;
- host copyrighted books;
- ingest arbitrary course catalogues;
- introduce affiliate commerce;
- create a public recommendation marketplace;
- treat content consumption as the developmental objective.

## Future expansion trigger

A richer learning-resource system should be considered only after pilot data shows that Builders repeatedly need structured learning support and the contextual Growth Pack improves Quest/Project completion or evidence quality.

Possible later layers, only with evidence:

- curated KAEC learning collections;
- verified provider/course catalogue;
- school/institution-assigned Growth Packs;
- save/complete/resource-feedback states;
- learning-resource analytics tied to later real-world evidence;
- recommendation quality review by trusted human curators.

Until then, the rule remains simple:

> **Do not send Builders away to consume more. Give them only enough learning to return stronger to the real-world adventure.**
