# Problem-Solving Engine — first implementation slice

## Purpose

Make PipuPath Quests lead to working interventions and honest learning,
not paperwork, vague tasks, or repetitions. Both Luna generation routes
use the same versioned quality instructions. Existing Quest contracts,
stored attempts, guardian requirements and the city remain unchanged.

## Changes

- A shared quality standard requires a real beneficiary, a concrete
  solution, observable baseline and comparison, safe existing resources,
  and improvement based on real outcomes.
- New Real Quest generation rejects obvious generic instructions, duplicate
  actions, absent build/test/improve signals. Existing bounded correction
  handles recoverable quality failures. New template keys use v7 so old
  generated templates are not reused for new goals.
- External AI Journey packs reject duplicate action sequences and bare
  generic instructions before persistence. Youth local generation stays
  local; existing authorisation and AI allowances are unchanged.
- Twenty problem contexts with five deterministic checks each. These are
  adversarial structural regressions, not 100 live generation evaluations.

## Acceptance and remaining work

- Run full CI and a staging-only review with actual Luna outputs across
  age, resource and domain constraints. Human reviewers must evaluate
  feasibility, relevance, safety and measurable outcomes; regex checks
  cannot establish those properties.
- Review the local youth Quest library and replace shallow activities with
  age-appropriate practical pathways without widening AI access.
- Design versioned persistence of discovery constraints, checkpoints and
  evidence-based progression. Do not promote self-report into verified
  competence, and preserve legacy attempts.
- Integrate the outstanding Financial Intelligence branch against current
  main only after the quality gate is accepted. Keep production untouched.
