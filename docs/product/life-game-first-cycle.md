# PipuPath: Game of life, first playable cycle

Candidate scope: onboarding, action guide and reflection. Not a separate game
product. Existing Mission → Journey → Quest → Evidence → Reflection → Capability
→ Project → Portfolio → Opportunity → Passport remains the durable engine.

## First cycle

Find your starting point → enter a real-world challenge → read one action at a
time → bring back evidence → answer one reflection at a time → reveal the next
server-unlocked challenge. Guide navigation earns no XP. Saved evidence and
completion retain existing server validation, authentication and reward rules.
No fictional wins, guaranteed earnings, punitive streaks or popularity scores.

## Onboarding review

Version 1 has 16 seeded questions; each age group sees 15 through RLS.
Version 2 has seven common questions plus one age-specific optional support
question: eight visible questions, seven required. Identity, neutral age band
and separate required consents remain unchanged.

| Keep                               | Why it changes the first challenge                  |
| ---------------------------------- | --------------------------------------------------- |
| important_now                      | A meaningful personal priority                      |
| activities_enjoyed                 | Motivation and interests                            |
| contribution_evidence              | One actual example instead of only self-description |
| values                             | What makes contribution meaningful                  |
| problems_noticed                   | A real-world problem to investigate                 |
| build_experiment                   | Willingness to try a practical direction            |
| weekly_time                        | A realistic commitment                              |
| learning_support / adult_resources | Age-appropriate support or resources                |

Defer current_focus, curiosity, relied_on_for, shaping_experience,
support_environment, guidance_needed and readiness_confidence from new
onboarding. Some overlap with retained evidence; others are better asked when
needed during a challenge. No later question feature is claimed in this slice.
Sensitive life-history questions are not required for a useful first action.

Version 2 copies eligible ages, options, validations, sensitivity and stable
question/category keys for the retained questions. Existing sessions and
responses stay on version 1. New sessions and later retakes select version 2
only after its migration is applied. Original question rows remain published
so historical/active sessions remain readable. Migration asserts exactly eight
questions per age. Rollback verification before publication left database on
version 1; rollout is a distinct step.

## Less text, more action

Discovery shows its question and choices, with supporting text behind “Need a
hint?”. Written answers use a shorter visible input without shortening allowed
answers. Quest action and safety appear before the phase action. Read one action
or expand the full plan. Proof and resources remain available as disclosures.
Reflection shows one prompt at a time; Back preserves typed text. All five
existing reflection fields are submitted to the same completion action. Drafts
are held in page memory, not saved automatically; the UI explicitly explains
when they are saved. Failed submission keeps answers available on that page.

## Operator validation

Run the normal validation suite, then use a disposable account to verify new
and resumed onboarding, proof, reflection, completion and next unlock. Confirm
an age-specific support question on a minor and adult test profile. Retest
narrow tablet/phone screens, keyboard navigation, large text and network failure.
Previously confirmed tablet results predate this candidate and do not cover it.

Pilot owner: institution facilitator. Technical owner: release/product operator.
Observe next-action understanding, time to first real action, evidence-backed
completion and return-to-action across two cycles. Compare against the earlier
interface; no improvement is claimed until observed. Weekly findings improve
the shared quest templates so facilitators can scale delivery without requiring
the founder to motivate every participant.
